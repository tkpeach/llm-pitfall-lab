模型知识导读：组件、任务路径、后训练与权重制品

本组笔记整理本轮围绕模型提出的问题。先建立通用机制，再用固定 Qwen3.5-4B 对照具体结构；数值诊断作为独立实践阅读。各主题正文只维护一份，本页连接它们，避免按聊天顺序反复抄写。

阅读顺序与问题定位

顺序 主题 要回答的问题
基础Tokenizer 与 Transformers从消息、模板和字节表示到 token IDs、模型输入和解码；库与模型文件如何配合？
1 多模态主干与图像生成 视觉编码器与语言主干如何协作？共享几个主干？读图与画图有什么区别？模态差别为什么不止 embedding？组件为何可以省略？

3 SFT、LoRA 与权重更新 训练目标与更新方式有什么区别？冻结基础参数为何仍参与计算？adapter、融合权重和完整恢复状态有何区别？
4 MLX、Metal 与模型执行 模型结构、计算框架和 GPU 后端各做什么？为什么 C++ 主路径仍需要辅助 Python 环境？
5 固定模型数值对照 如何逐层观察并诊断低精度和缓存差异？为何小算例通过不等于完整模型正确？为什么要先测参考自身的分块漂移？

把概念连在一起

任务需要什么输入和输出
  → 决定需要哪些编码器、主干和输出组件
  → 用配置、模型代码和权重索引核对完整计算路径
  → 将源权重适配为运行框架需要的表示
  → 若量化，明确其近似与存储约定
  → 若后训练，另选训练目标和可更新参数
  → 分别验证前向、状态、梯度、更新和恢复

这里有三组不能混用的判断：参数能按名字筛选，不说明任意层可删；权重格式转换通过，不说明任务效果不变；前向一致，不说明训练反向或新进程恢复已正确。Qwen 专题给出前两组的具体例子，数值对照与 LoRA 笔记解释后一组。
