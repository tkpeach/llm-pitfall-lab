# 重要决策记录

本目录保存跨阶段或有长期影响的项目决策及其演变，供人和 agent 理解背景与取舍。当前要求由 [正式文档](../docs/README.md) 的专题维护，当前实施与验收见 [仓库现状](../docs/status.md) 和 [当前证据](../evidence/current.json)；决策记录不自行改变规范或证明实现完成。历史材料与现行要求冲突时，查后继决策和当前规范，不以历史替代当前要求。

## 何时记录

模型、硬件、范围、验收或资源限制变化，跨模块架构与职责选择，以及对正确性、效果、时间、资源、恢复或证据有效性有长期影响的取舍，应新增或更新记录。局部重构、一般修复、单次运行和操作流水不单独记录。写新记录时先检查同主题旧记录；部分取代须指出仍有效部分，全部取代保留原记录并双向链接后继。当前规范与相应状态、证据按现有维护流程同步。

## 状态与格式

文件名为四位编号加英文主题，例如 `0001-topic.md`；编号唯一。每条使用以下字段及章节：

- `决策状态：` 提议中、已确认、已拒绝、已部分取代或已取代。提议和拒绝不构成当前要求；已确认不等于已实现。
- `实施状态：` 未实施、部分实施、已实施或不适用；详细状态以仓库现状为准。
- `决策日期：` 可信日期或“未知”；事后补录须明确标识。
- `当前规范：` 相关专题链接；`后继：` 无或相关决策链接。已部分取代和已取代必须有后继链接。
- 章节依次包括“问题与背景”“决定”“考虑过的方案”“依据与不确定性”“后果与重新评估条件”。新决策记录真实考虑的替代方案及原因，没有有意义替代时说明；无法恢复的历史明示未知，不能编造。

活跃记录的当前规范链接、入口和适用说明可随变化修正；当时的决定、真实替代方案和证据保留历史语境。实质性改变新建后继记录，旧记录更新状态和链接，不改写成相反决定。事实纠正说明依据；Git 保留修改历史。记录日期、条件及证据身份，不把推断写成原始决定。当前快照会覆盖，历史依赖时保存必要的小型摘要及可追溯来源，不把可清理的 `runs/` 当作唯一证据。

## 信息归属与历史边界

决策记录保存重要选择的理由及演变；当前要求和实施状态分别以正式专题文档与仓库现状为准。`research/` 保存调研和实验材料，历史结果不自动成为当前验收。`learning/` 维护可复习的知识和案例，不建立决策历史或历史版本归档。其他内容按 [目录职责](../docs/README.md#项目目录职责) 维护；普通版本变化由 Git 保存，重要取舍按上述条件记录。

检索当前行为先读当前文档、代码及证据；追溯理由读有效决策及其前驱；历史实验按原始环境和条件解释。检查器只检查结构与链接，不判定事实、批准或证据是否充分。
