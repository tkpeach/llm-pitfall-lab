# LLM Pitfall Lab

围绕具体软硬件环境，学习 LLM 推理与微调（后训练）的实验项目。

目标是理解完整过程，建立观测、诊断和优化能力，并明确经验的适用条件，使其能够为更大 LLM 的相应过程和小模型的类似过程提供参考。

## 当前状态

初步需求基线已确认，下一阶段为资源与选型可行性验证，尚无可运行的推理或训练实现。模型、硬件、软件组件、实验数据及具体算法尚未选定。

当前限定为文本模型。多模态、大规模并行/分布式执行不在当前两期实施和验收范围内；现有资源不支持分布式运行与验证。

在已确认的学习目标与验收框架下，进行资源和选型验证，逐步形成可复现的实验链路。具体指标在可行性验证后确定。

## 学习范围

- **一期推理**：模型执行、自回归生成、Prefill 与 Decode、KV cache、离线批处理、性能分析、精度及针对性优化，并保留前沿优化方向的扩展空间。
- **一期后训练**：数据与训练目标、SFT、LoRA、训练资源管理、诊断与恢复、效果评估，以及受控在线强化学习实验。
- **MoE**：一期保留推理机制与观察目标，实际深度结合资源确定；MoE 后训练放在二期。
- **可解释性专题**：贯穿项目持续操作、记录和比较观察结果，逐步完善观察方式；当前不要求深入方法原理、自行实现或开展优化。
- **二期专题**：一期验收后开展多请求调度、离线偏好优化和 MoE 后训练，一期架构预留相应边界。

推理与后训练投入相当。部署以可重复启动的本地程序或接口为目标，验证训练产物在新进程中的加载与评估，不要求图形界面或生产服务平台。实验任务用于学习和验证，不以构建通用高能力助手为目标。

## 实践方式

每个主题按需组合三种方式，不要求从零实现完整框架：

1. **最小机制实验**：用小规模代码或受控实验隔离问题，验证机制与预期行为。
2. **真实链路观测**：在目标模型与环境中追踪执行、资源消耗和结果，建立可核对的认识。
3. **针对性修改与优化**：根据观察提出假设，通过配置或局部代码修改验证收益与取舍。

按学习需要复用成熟组件与参考实现。以能否解释、操作、观测和验证作为学习标准，不以自研代码量衡量深度。

## 实验原则

- 以已知正常行为链路作为基线，保留正确路径，避免兜底掩盖主路径问题。
- 围绕固定目标优化，不建设多硬件、多模型通用兼容框架。
- 保存复现条件与对照证据，结合正确性、任务效果、速度和内存分析结果。
- 记录失败、无收益和负收益实验，说明原因与适用边界。
- 区分实测事实、解释假设和未验证推断，不将局部结论直接推广到其他规模或环境。
- 可解释性观察采用独立的过程验收，不要求发现确定机制；观测开销与性能测量分开记录。
