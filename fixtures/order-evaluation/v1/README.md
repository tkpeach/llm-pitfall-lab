# 中文订单抽取评估种子集 v1（候选）

当前包含 52 条合成样本、26 个底层订单/改写组：开发集与测试候选集各 26 条、13 组，每组两个改写。它与 [六条契约样例](../../task_contract.json) 分开，目的是逐步建设可审查的效果评估数据，不替代原有解析器错误用例。

**状态：待独立人工复核，测试候选集尚未冻结；未运行目标模型，不宣称已验证业务泛化。** 内容由 assistant 为本项目原创合成并作规则核对，不是人工标注的外部数据集；未使用第三方数据集或私有业务信息，沿用本项目合成样例的项目内使用方式。来源与审核状态明确保存在 manifest 中，不伪称外部许可或独立审核已完成。

## 文件与使用

| 文件 | 内容 |
| --- | --- |
| [dev.json](dev.json) | 可用于人工审查、开发期提示和错误分析的输入与 gold |
| [test.json](test.json) | 预留的测试候选；不用于提示选择、few-shot 示例、训练或奖励优化 |
| [annotations.json](annotations.json) | 样例 ID、改写组、场景/规则标签、字段证据、null 理由及复核状态 |
| [manifest.json](manifest.json) | 数据身份、来源、版本、集合统计与内容哈希 |

两个 gold 文件直接使用现有原生 `evaluate` 的输入格式；标注信息独立保存，避免为数据元信息修改评分协议。开发阶段使用：

```sh
./runs/d1/build/pitfall-lab evaluate \
  --gold fixtures/order-evaluation/v1/dev.json \
  --predictions your-dev-predictions.json
```

预测文件由实际模型生成后准备，不能把 gold 自对照结果当成模型得分。构建方式和预测文件要求见 [构建指南](../../../docs/build.md#离线任务评估)。

## 覆盖与标注政策

每个集合覆盖完整 CNY/USD 订单、缺失字段、仅有总价、币种不猜测、相对日期、数量/单价明确更正、编号与规格数字干扰、中文数量、零单价以及绝对日期选择；另含无订单信息。开发集有合法闰日样本，测试候选有月末日期样本。集合刻意覆盖规则，不声称符合真实业务频率或难度分布。

- 商品名取原文中明确给出的名称，保留型号、颜色等名称内信息，去除引号和计量单位。只选边界清楚的句子，不用同义词替换答案。
- 编号保留大小写、连字符与前导零；数量与单价分别引用最终有效证据。明确更正时使用更正值，不把一般矛盾当成更正。
- 金额使用十进制精确转成两位最小单位。没有单价时不从总价推导；零单价与未提供单价不同。
- 币种只依据 CNY/人民币或 USD/美元，孤立符号与收货地不能作为依据。为避免未定币种下最小单位含义不清，本种子集不收录“明确金额但币种未知”的单价样本。
- 日期只选明确的绝对送达日期，不把下单日、会议时间或相对时间填入。
- 多商品、混合币种、无法消解矛盾和高于两位小数的金额继续留在 v1 范围之外。

## 质量检查与边界

`task.dataset` 检查哈希、ID/文本去重、同组 gold 一致及集合隔离，核对证据是否存在、所引数字与日期是否能转为 gold，要求每个 null 有理由，并调用原生评估器检查 gold 合法性。`checks.dataset_failure_cases` 用人为破坏的临时副本确认检查器确实会拒绝错误。

这些检查不是自然语言语义裁判：它们不能证明证据选取正确、没有遗漏应抽字段、改写没有歧义、样本独立且有代表性。gold 自对照满分也只说明输入格式和汇总可用。独立人工审核仍是冻结测试集前的必要步骤。

## 复核与冻结流程

1. 逐组核对原文到六字段的语义和边界，重点检查更正、null、金额和日期。当前所有记录明确标为独立人工复核待完成，不由脚本自动转为“已审核”。
2. 发现歧义先修正样本或标注规则，并记录数据版本；不得为了匹配模型答案临时放宽评分。首次使用前可在该候选版本修订，冻结后内容变更须发布新版本和新 manifest。
3. 确认同一订单的全部改写属于同一集合，且不与契约样例、训练数据/few-shot 改写重叠。未来训练集必须显式检查组和来源；当前未创建训练集，不承诺已证明与未知未来数据隔离。
4. 完成复核后，记录审核人/方式、结论、日期与冻结哈希；测试集首次运行前固定提示、采样和主要指标。开发和调参使用 dev，禁止根据 test 表现反复挑样本或改规则。
5. 测试文件在仓库中可读，不是权限隔离或保密存储。“封存”依靠上述流程；当前尚未完成封存。若测试内容已用于针对性调参，应另建独立版本并重新建立基线。

正式数据规模、难度及是否继续扩展由目标模型的开发集基线决定。后续诊断指标、语义裁判等只作方法参考，本轮不实现。
