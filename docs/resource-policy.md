# 资源使用规则

相关历史与取舍见 [决策记录](../decisions/0003-resource-recovery.md)；当前要求以本文件为准。

本文件定义资源约束与恢复要求，实际实现状态见 [仓库现状](status.md)。

## 1. 已确认原则

- 使用当前 M4 / 24 GiB Mac 完成既定学习范围。
- 内存适配同时评价时间、系统响应、任务效果和磁盘成本。
- 重负载实验安排在用户指定的空闲窗口；常规实验接受小时级，少量空闲实验约 8 小时。
- 磁盘、GPU 和交换空间留有系统余量；涉及用户文件的清理须先确认归属和保留计划。

## 2. 磁盘预算与检查

| 项目 | 规则 |
| --- | --- |
| 项目物理占用参考预算 | 20 GiB |
| 项目占用提醒值 | 18 GiB |
| 所在卷剩余空间安全线 | 30 GiB |
| 超出项目参考预算 | 提醒检查占用和后续产物计划；预算本身不拒绝操作 |

项目占用值是经验参考。阶段性检查总体占用，记录当前值、变化和建议处理方式。下载、转换、融合、检查点等大额写入开始前，核对卷可用空间和预计新增峰值。峰值估算覆盖临时文件、并存的源与目标、转换缓冲及最终保存；保存恢复状态时同时考虑新旧状态和暂存副本。

卷剩余空间安全线独立于项目参考预算。预计写入将突破安全线时，调整写入计划或在安全边界暂停；阶段性检查与处理建议应考虑外部进程可能占用卷空间。

机器可读值见 `configs/resources.toml`。

## 3. 占用归属与保留策略

- 项目总体占用包括 `.venv`、项目包缓存、模型与数据缓存、权重、转换中间产物、数据、检查点、运行日志和观察产物，以及项目产生的外部文件。
- 新增模型、数据和工具缓存优先放入项目受管理目录；外部归属目录登记来源和占用，并纳入阶段盘点。
- 每阶段保留一个活动模型。模型迁移时可保留复现所需的 4B 量化权重与 adapter，并按实验计划管理其他版本。
- 优先保留 adapter、配置、评估结果、诊断记录和观察摘要，以及最新可恢复状态和明确标记的最佳/里程碑产物。
- 完整恢复状态包括模型/adapter、优化器与调度状态、全局进度、随机状态、数据位置/顺序及模型、数据、模板和配置身份。
- 原始 BF16、融合模型、完整激活与 profile 按明确实验计划生成，并为产物设定保留周期。
- Git 保存代码、配置、小型证据、来源 revision 和必要校验信息；权重、数据、缓存与大型运行文件保留在 Git 外。

## 4. 安全暂停与恢复

- 用户提出暂停后，在最近安全边界保存完整恢复状态、退出工作进程并释放模型与 GPU 资源；用户明确继续后再启动恢复。
- 记录暂停请求到安全退出的延迟，并在短验证中确定安全单元长度。
- SFT 在优化器更新边界保存；梯度累积未完成时，保存累积状态或明确重做未提交更新。
- 在线强化学习在可恢复迭代边界保存策略版本、奖励和进度；跨迭代暂停时保存必要 rollout 状态，或明确重做未提交迭代。
- 评估与观察按样例或小批次保存进度。长生成记录完成结果和重启方式，缓存持久化单独验证。
- 检查点保存使用完整性校验和安全提交；恢复前核对产物身份与完整性，不兼容或损坏时明确报错。
- 连续运行与中断后新进程恢复对照参数、优化器、步数和数据消费情况，并核对资源释放和暂停延迟。

## 5. 大文件与长运行

下载、转换和完整模型运行前核对卷空间与预计峰值；长训练前完成目标模型短更新和完整恢复验证。长运行按阶段安排，并在启动前完成短验证。内存、时间、前台响应和暂停延迟阈值依据短基线确定；模型迁移时重新建立基线。
