# 资源使用规则

本文件定义资源约束与恢复要求，实际实现状态见 [文档总入口](README.md)。

## 1. 已确认原则

- 使用当前 M4 / 24 GiB Mac，不以新增硬件作为当前计划成立的条件。
- 内存适配属于学习与优化范围，但同时评价时间、系统响应、任务效果和磁盘成本。
- 本机还用于用户其他工作，以可安全暂停、释放资源和继续满足共存需要；重负载实验放在用户安排的空闲窗口。
- 常规实验接受小时级，少量空闲实验约 8 小时；不是每周投入，也不是任意后台长运行的授权。
- 不占满磁盘，不自动删除用户其他文件，不自动修改系统 GPU 内存或交换设置。

## 2. 磁盘限制（已确认）

| 项目 | 规则 |
| --- | --- |
| 项目物理磁盘总预算 | 20 GiB |
| 预算预警 | 18 GiB，进入清理/保留决策，不继续无计划累积 |
| 所在卷剩余空间底线 | 30 GiB |
| 超限动作 | 不启动新的下载、转换或产生大文件的实验；不以自动删除用户文件补足额度 |

阈值是本项目约束，不代表系统通用安全标准。卷空闲量按操作前实测，不把历史快照当作可用额度；机器可读值见 `configs/resources.toml`。

下载、转换、融合或运行前应满足：`预计新增峰值 <= min(项目预算 - 当前归属占用, 卷空闲空间 - 剩余空间底线)`。预计峰值需覆盖下载临时文件、原始与目标同时存在、转换缓冲落盘及最后保存，而不只是最终文件大小。额外不确定余量在具体操作计划中列出。

运行中在可检查边界复核空间。保存恢复状态时需预留预算，不能在磁盘临界后才尝试写出大检查点；单个库调用的大额写入也不能依赖事后轮询保证不越界。

## 3. 占用归属与保留策略

- 项目预算覆盖 `.venv`、项目包缓存、模型/数据缓存、权重、转换中间产物、数据、检查点、运行日志和观察产物，包括项目产生但位于仓库外的文件。
- 新增模型、数据和工具缓存优先放在项目受管理目录，不静默散落到用户全局缓存。需要外部目录时记录来源与占用，不能通过移出仓库规避预算。
- 同时检查卷空闲和项目归属文件的分配块占用，按文件身份去重硬链接；对无法准确识别的 APFS 共享块等采取保守估算，不声称精确计算全部共享物理空间。逻辑大小不能替代写入峰值估算。
- 外部归属目录通过 `extra_owned_paths` 显式登记；当前预算只覆盖同一卷，其他卷须单独制定预算，不把路径移出仓库视为额度释放。
- 每阶段一个活动模型，迁移时可保留复现所需的 4B 量化权重与 adapter，不默认保留两个模型的全部精度版本。
- 日常优先保存 adapter、配置、评估结果、诊断记录和观察摘要。保留最新可恢复状态及明确标记的最佳/里程碑产物，具体保留数量由任务预算确定，不无限留存。
- 仅保存 adapter 不等于精确恢复训练；恢复状态的内容和体积必须列入预算。
- 原始 BF16、融合模型、完整激活与 profile 仅为明确实验生成，完成后按预先定义的项目产物生命周期处理；不得删除未确认归属或含唯一修改的文件。
- 不将权重、数据、缓存和大型运行文件加入 Git；Git 保存配置、代码、小型证据、来源 revision 与必要校验信息。

## 4. 安全暂停、释放与继续（必需能力）

用户需要资源时安全暂停并退出，之后显式继续，是主要共存方式；不要求与其他高负载应用持续并发。

- 支持用户主动提出暂停请求，在最近安全边界保存，退出工作进程，并确认模型内存与 GPU 资源已释放。仅挂起进程、保持权重或缓存驻留不算满足要求。
- 不保证立即中断正在执行的 GPU 算子；测量并报告暂停请求到安全退出的延迟。如果安全单元过长，应缩短单元或细化保存边界，再开展长实验。
- SFT 首选完整优化器更新边界。保存可训练参数/adapter、优化器与调度状态、全局进度、随机状态、数据位置/顺序及模型、数据、模板、配置版本。梯度累积未完成时，应保存累积状态，或明确重做尚未提交的更新，不重复或跳过已完成更新。
- 在线强化学习选择可恢复的迭代边界，记录采样策略版本、奖励与进度。允许迭代中暂停时，须保存必要 rollout、旧策略概率等，或明确重做未提交迭代；不能静默混用不同策略采集的样本。
- 评估与观察按样例或小批次分段保存。长生成记录完成结果与重启方式；缓存持久化单独验证，不承诺任意生成位置精确接续。
- 保存采用完整性校验和安全提交方式，磁盘预算包含临时文件与旧检查点同时存在的峰值；提前为恢复状态预留空间。
- 恢复前验证产物身份与完整性，不兼容或损坏时明确失败，不能静默从头训练。仅保存 adapter 不等于完整恢复。
- 正常暂停后不自动恢复；用户明确继续后再加载。强制结束、崩溃或断电仅从最近有效保存点恢复，不承诺未保存工作的无损接续。
- 验收比较连续运行与中断/新进程恢复的参数、优化器、步数和数据消费情况；数值按声明容差比较，并核对资源释放与暂停延迟。

需要后台训练时可另做共存短测；未验证配置不宣称前台流畅。MLX 分配峰值不等于进程 RSS 或系统内存压力，内存上限也不单独保证 GPU/CPU 资源公平。

常规实验小时级，少量空闲重负载约 8 小时，均先通过短验证再分段运行；不擅自创建计划任务或常驻后台进程。具体暂停延迟和单段预算在短测后确定。

## 5. 大文件与长运行门槛

下载、转换和完整模型运行前，先验收对应资源预检；长训练前，先验收目标模型的短更新和完整恢复。辅助小实验不替代这些关口。内存、时间和暂停延迟阈值由短基线制定；不为跑通 9B 自动放宽已确认限制。
