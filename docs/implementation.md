# 实现约定

## 语言与职责

- C++ 为正式实现主语言，负责固定模型装配、推理与训练步骤、缓存、资源保护、检查点、运行控制和观察接口。
- MLX 提供张量计算、自动微分和已有 CPU/GPU 算子；目标执行设备为本机 Apple M4 GPU。
- GPU 执行使用 MLX 的 Metal 后端。自定义 MSL 内核只通过项目计算扩展层接入，用于性能分析后确定的局部优化，不要求从零实现完整计算后端。
- Python 用于参考数值对照、数据准备、实验验证和离线分析；不承担正式模型推理与训练的执行主路径。
- 正式构建使用 CMake 与 C++23，所用语言和标准库特性在固定工具链上验证。固定目标所需的模块直接实现，不建设多后端、多模型适配框架。

## MLX 与 MLX-LM 的复用边界

正式链路基于 MLX 的 C++ 接口实现固定模型所需的推理与后训练功能。MLX-LM 用于实现参考和显式运行的数值对照；正式 C++ 程序不通过 Python 绑定、子进程或服务调用 MLX-LM 完成模型推理与训练。不复制完整 MLX-LM 框架，也不以自研代码量衡量学习成果。

| 能力 | 实现与复用方式 |
| --- | --- |
| 张量、自动微分、已有 CPU/GPU 算子 | 直接使用 MLX；局部扩展遵循下述计算扩展边界 |
| 权重映射、模型装配、前向计算 | 参考可靠实现，在 C++ 中实现固定模型需要的结构和加载契约 |
| Prefill、Decode、KV/卷积/递推状态、采样与停止 | 在 C++ 中组织生成与状态管理，保留观察和数值对照入口 |
| LoRA、loss/mask、梯度累积与训练步骤 | 基于 MLX 实现；优化器优先复用经过验证的原生能力，缺失时只实现所需算法 |
| 检查点、暂停恢复、资源保护 | 按项目契约实现，不以参考框架的默认行为代替验收 |
| 分词、JSON、文件格式等支撑能力 | 优先复用可供 C++ 正式链路使用的成熟组件，核验许可、兼容性与资源成本，不默认自研 |

参考程序与正式程序分开执行，通过显式输入和结果文件对照，不形成正式运行时依赖。记录参考代码来源、版本或 revision、权重与量化身份、输入、模板、dtype 和容差；参考环境和产物同样计入资源预算。参考实现不能被假定为绝对正确，关键小算例结合解析结果或独立检查验证；不能以两条路径共享同一错误作为正确性依据。

推理支持与训练支持分别验证。量化执行产物能够生成文本，不代表相关算子具备训练所需的梯度或能够进行 LoRA 更新；实际量化布局、梯度路径与 adapter 重载须通过目标链路短验证。详细验证顺序见 [一期设计](design.md#模型与训练的数值对照)。

## GPU 计算扩展边界

模型和训练代码以数学运算与张量语义表达计算，不直接管理 Metal 设备、pipeline、线程组或内核源码。MLX 已承担通用张量后端抽象；项目另设薄的计算扩展层，集中管理自定义内核及有版本差异的专用接口，不逐项重封装整个 MLX API。

计算扩展层对上暴露有明确输入输出、shape、dtype、状态和梯度契约的 C++ 函数；实现内部处理 MSL 源码、编译缓存、设备能力、dispatch、同步与错误。支持自动微分的扩展同时定义反向规则，不将仅有前向的内核直接用于训练。保持张量驻留和梯度链路，不为接口抽象增加 CPU 往返或多余复制。

模型、训练及资源管理模块不散布 Metal 专用细节。MLX 或 Metal 接口升级时，先修改对应集成位置并重跑数值、梯度与资源验证；不承诺任意版本升级都只需修改一层。当前只实现 M4 / MLX / Metal 路径，不引入通用后端插件、虚拟分派或未使用的平台接口。

## 工具环境

根目录 `pyproject.toml`、`uv.lock` 和 `.python-version` 定义辅助环境，MLX 固定为 0.32.4、MLX LM 固定为 0.32.2。该环境提供 MLX C++ 头文件、动态库和 Metal 库，并提供 Python 数值对照能力；它不是项目的 Python 应用包，不注册正式运行命令。

`requires-python = ">=3.12,<3.13"` 是当前已验证工具环境的支持范围，不是 MLX 只能使用 Python 3.12；`.python-version` 指定本机默认选择 3.12。暂不承诺多 Python 次版本兼容。需要升级时显式验证依赖、SDK 定位和数值对照，并更新环境记录；Python 次版本不能成为 C++ SDK 路径中未检查的隐含假设。

`uv.lock` 保存已解析的直接与间接 Python 依赖、精确版本、来源及包文件哈希，应提交 Git；`.venv/` 不提交。用 `uv sync --locked` 按当前有效锁文件同步环境，配置与锁文件不一致则报错。锁文件不固定编译器、macOS、Python 解释器二进制或执行确定性，这些复现条件单独记录。

当前 SDK 位于 `.venv/lib/python3.12/site-packages/mlx/`。C++ 工作进程直接链接 `libmlx.dylib`，不嵌入 Python 解释器。正式构建应显式定位 SDK，并核对本机 framework 路径；不能假定包中构建机器的绝对 SDK 路径可在本机使用。SDK 和工具环境占用计入项目磁盘预算。

实际构建通过 `cmake/mlx/locate_sdk.py` 获取所选环境的 SDK 位置，不在 CMake 或原生代码中拼接 Python 次版本目录；固定路径和版本在配置阶段核验。命令与检查范围见 [构建与检查](build.md)。

`src/` 与 `tests/` 用于正式 C++ 实现及其测试。辅助脚本按功能放置，不能以 Python CLI 或旧参考实现替代 C++ 主路径。

## 配置与任务数据

`configs/resources.toml` 是机器可读的项目资源规则，与 [资源使用规则](resource-policy.md) 保持一致：

| 配置项 | 作用 |
| --- | --- |
| `project_limit_bytes` | 项目归属文件的物理占用上限，20 GiB |
| `warning_bytes` | 占用预警阈值，18 GiB |
| `min_free_bytes` | 所在卷必须保留的空闲空间，30 GiB |
| `extra_owned_paths` | 位于项目目录外、但仍须计入额度的项目文件目录；当前为空 |

辅助可行性验证器显式读取此配置；正式保护由 C++ 资源模块负责，验收按 [一期设计 D2](design.md) 执行。

正式实现由 C++ 资源模块统一加载、校验策略并核算项目物理占用、卷空闲及操作峰值。下载、转换、检查点和大额产物写入必须通过受控操作入口申请预算并执行检查；运行控制在安全边界复核，配置缺失、非法或额度不足时明确拒绝。并发写入须协调预算，检查点同时预留新旧状态和临时提交空间。CLI 负责接入统一运行上下文，不能只在进程启动时检查一次就视为全部操作受保护。

这些是应用层保护，不能替代文件系统硬配额，不能阻止其他应用写盘，也不约束用户绕过入口运行任意命令。操作应留有余量并处理实际写入失败，保护最近有效检查点。此 TOML 当前只定义磁盘规则，不定义 GPU 内存或算力硬限制。

首次安装 SDK、同步环境和构建发生在正式程序可用之前，须显式核对预计写入与当前空间；可使用辅助预检，不声称这些命令已受尚未建立的 C++ 资源模块保护。

目标模型身份由 [模型路线](model-plan.md) 定义。正式模型配置只记录验收所需的固定身份与实际加载参数，在加载链路实现时接入；未执行的参考模型配置不放在正式 `configs/` 中。

`fixtures/task_contract.json` 是中文结构化抽取的手写契约样例，规范见 [任务契约](task-spec.md)。它与实现语言无关，应由 C++ 评估器沿用，不作为训练效果数据集。
