# 项目文档总入口

本文件是 `docs/` 的唯一总入口，负责文档导航、项目目录职责与当前实施位置。仓库首页是 [根 README](../README.md)，协作约束见 [AGENTS.md](../AGENTS.md)。新对话接手项目时，从这三个入口读取当前仓库，不依赖之前的聊天记录推断项目结构或决策。

## 阅读顺序与内容归属

先读取根 `AGENTS.md` 和本文件，再按任务阅读对应规范；首次建立或调整主链路前应阅读下表全部文档。

| 顺序 | 文档 | 负责回答的问题 |
| --- | --- | --- |
| 1 | [学习规格](learning-spec.md) | 项目要学什么、交付什么、如何验收，各期范围和限制是什么 |
| 2 | [模型路线](model-plan.md) | 每期固定哪个模型、原始权重身份是什么、迁移边界是什么 |
| 3 | [资源规则](resource-policy.md) | 磁盘预算、产物保留、安全暂停与恢复必须满足什么 |
| 4 | [实现约定](implementation.md) | C++23、MLX、Metal 和 Python 如何分工，构建、环境及配置如何组织 |
| 5 | [任务契约](task-spec.md) | 中文抽取任务的字段、归一化、数据边界和评估规则是什么 |
| 6 | [一期设计](design.md) | 模块如何划分、计算和状态如何流动、实现通过哪些验证关口 |
| 7 | [构建与检查](build.md) | 如何构建原生程序、运行 CLI 和 CTest |

各文档分别维护所属领域的具体规则，本入口不重复定义。需求和约束决定设计，设计不能自行放宽需求。若文件间出现冲突，应核对用户已确认要求并修正文档，不从历史调研或旧代码中任选一个版本作为当前规范。

## 项目目录职责

| 位置 | 职责与使用边界 |
| --- | --- |
| 根 `README.md` | 项目简介、范围概览和本入口链接 |
| 根 `AGENTS.md` | 长期工程原则、学习实践方式及接手项目的必读指引 |
| `docs/` | 当前有效的需求、约束、实现约定、任务规范和设计；不放选型讨论过程 |
| `configs/` | 正式机器可读配置；当前 `resources.toml` 定义磁盘规则，文件存在不代表保护已实现 |
| `fixtures/` | 语言无关、可人工审查的契约样例；不等于训练集或效果评估集 |
| `src/`、`tests/` | 正式 C++ 实现与测试，按模块维护构建定义；正式运行不调用测试 |
| 根 `CMakeLists.txt`、`cmake/` | 项目构建、MLX SDK 集成及构建信息 |
| 根 `pyproject.toml`、`uv.lock`、`.python-version` | MLX C++ SDK 供应与 Python 辅助工具环境，不是正式 Python 应用 |
| `.venv/`、`.cache/` | 本机环境和缓存，不提交 Git，占用计入项目预算 |
| `research/` | 历史调研、有限机制验证及旧原型；正式运行不得导入代码、读取运行时配置或隐式依赖其环境 |
| `runs/` | 本机构建文件、实验输入输出、报告与检查点，不提交 Git，占用计入项目预算 |

参考资料按用途分别存放：

- [模型选型归档](../research/model-selection/README.md)：候选评估和模型可行性探测。
- [C++ / MLX 机制验证](../research/cpp-feasibility/README.md)：原生计算、梯度、状态恢复等实验和证据。
- [旧 Python 原型](../research/python-prototype/README.md)：仅供阅读与局部对照，不是第二套正式实现。

历史实验可显式复现，但其结论不能自动计入正式 C++ 模块或完整目标模型的验收。

## 维护规则

新增、移动或删除文档时同步本索引。目录职责或实施进度变化时更新本文件；具体规则只在所属专题文档维护，根 README 保留概览，AGENTS.md 保留长期协作约束。

### 代码与文档的一致性

文档定义要求，配置定义运行参数，代码实现行为，验证结果提供证据。发生冲突时先定位原因：修正偏离要求的实现，或依据已确认的变更更新规范；不能改写文档掩盖错误，也不能把设计标成已实现。

每次变更的完成条件：

1. 明确受影响的规范、配置、接口、使用命令和证据；只修改相关内容。
2. 完成实现及相应验证，同步受影响文档和示例；无需修改文档时说明理由。
3. 提交前审查完整差异，代码与对应文档尽量在同一提交交付；涉及进度时更新本入口。

检查随正式模块就绪接入统一本地入口和 CTest：

| 接入时点 | 检查内容 |
| --- | --- |
| D0 | 文档链接和索引、依赖锁、SDK 与实际 C++ 标准；正式目标不依赖研究目录 |
| D1–D2 | 任务样例与评估器契约、资源配置校验、额度拒绝和检查点失败行为 |
| D3 | 退出和新进程恢复正确性；CLI 就绪后验证文档中的关键命令 |
| D4–D5 及后续实验 | 目标模型身份、数值与任务效果、资源和时间结论与实际证据一致 |

参数表可由 TOML、CMake 或依赖清单生成/校验；不依靠对任意自然语言的脆弱匹配。静态扫描只辅助检查，行为承诺仍需执行验证。纯文档调整检查链接、导航和内容，不因此重跑完整模型。

证据记录代码版本及工作区修改、必要源码摘要、工具链、模型/配置身份、命令、输入与容差。大产物存 `runs/`，需要提交的结论保留小型摘要及证据定位；不能只依赖可能被清理的本机目录。相关代码或配置变化后，复验受影响结论，或标明证据仅适用于旧版本。

统一检查通过 CTest 执行，命令与范围见 [构建与检查](build.md)。D0 不等于完整模型验收。
