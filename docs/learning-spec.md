# 学习目标与验收规格（讨论稿）

状态：v0.2，供需求讨论；不代表具体模型、硬件、算法及全部实验已经确定。

## 1. 项目目标与确认状态

通过目标模型在确定软硬件环境中的推理和后训练实践，理解完整执行过程，建立基于证据的诊断与优化能力。经验应能为更大模型的相应过程及小模型的类似过程提供参考，同时明确迁移条件。

已确认：

- 推理与后训练投入相当，以机制理解、实际操作、过程观测和结果验证为核心。
- 按需组合最小机制实验、真实链路观测、针对性修改与优化，不要求从零实现完整框架。
- 聚焦特定软硬件及模型，不建设多平台、多模型兼容体系。
- 推理优化能够容纳后续前沿方向；MoE 纳入规划，深度待定。
- 在线强化学习纳入计划内的受控实验阶段。
- 模型可解释性作为独立专题贯穿项目，持续操作、观察和完善观察方式；当前不要求方法原理理解或优化。

下文的主题拆解、验收方法和完成标准均为建议，尚待用户确认。DPO、具体优化算法、多设备实验及任务类型未确定。

## 2. 能力目标

| 编号 | 完成后应具备的能力 | 可检查的证据 |
| --- | --- | --- |
| C1 | 解释输入如何经过模型执行变成输出，以及哪些状态在变化 | 对应实际运行记录的执行链路说明 |
| C2 | 解释训练数据如何产生 loss、梯度、参数更新及行为变化 | 可检查样本、训练步骤记录与独立评估 |
| C3 | 根据模型、序列、批量和精度估算资源，并解释估算与实测差异 | 资源预算、测量与差异分析 |
| C4 | 区分模型能力、数据、实现、数值和系统性能问题 | 至少覆盖推理与训练的完整诊断案例 |
| C5 | 从负载与 profile 提出优化假设，选择方法并验证取舍 | 基线、优化实验、质量与资源对照 |
| C6 | 判断经验在规模或环境变化后是否仍适用 | 迁移分析及可执行的验证方案；未测部分明确标注 |
| C7 | 操作选定的可解释性观察方法，记录结果并比较阶段变化 | 可复现的观察记录、跨阶段对照、方法版本与解释边界 |

不以泛读论文、成功启动服务、训练 loss 下降或开启某项优化单独作为完成依据。不要求预先保证每次优化都取得正收益，或每次训练都提高任务效果。

## 3. 推理学习主线

| 编号与主题 | 需要理解 | 实际操作与观察 | 建议验收证据 |
| --- | --- | --- | --- |
| I1 输入与模型执行 | tokenizer、对话模板、权重、位置编码、Attention、MLP、输出概率 | 追踪一个实际输入的 token、关键张量和输出；检查加载与精度 | 输入到输出的可核对记录；一个模板或加载问题诊断 |
| I2 生成过程 | 自回归、Prefill、Decode、采样与停止 | 分阶段计时；改变输入与输出长度；检查生成轨迹 | 首 token 与逐 token 延迟、阶段耗时及影响因素分析 |
| I3 KV cache | 缓存内容、位置、mask、生命周期、容量与带宽开销 | 对照有无缓存；改变上下文和批量；检查缓存状态；注入位置或复用错误 | 数值对照、时间和内存曲线、缓存错误定位记录 |
| I4 请求与缓存管理 | 变长序列、批处理、请求生命周期、缓存分配与回收 | 在受控多请求负载下观察等待、执行与结束；比较一种管理或调度策略 | 延迟分布、吞吐、缓存占用与正确性检查；明确是否包含排队时间 |
| I5 瓶颈与执行优化 | 计算、内存带宽、数据搬运、算子与启动开销 | 采集 profile；选择一个实际瓶颈开展局部优化 | 可重复基线与优化结果；解释收益或无收益原因 |
| I6 精度与近似 | 权重、激活和缓存精度的不同影响；误差与质量 | 针对一个选定对象比较精度或量化方案 | 内存、性能、数值与任务效果联合对照 |
| I7 扩展优化实验 | 新方法的机制、前提、正确性及成本 | 在完成基础主线后接入一个选定方法 | 方法适用条件、与基线的对照、失败边界和扩展记录 |

I4 的具体深度需讨论：基本批处理和生命周期是完整链路所需；连续批处理、分页缓存、前缀复用与分块 Prefill 的实现或观测范围待定。

I7 候选包括推测解码、缓存压缩、编译与图执行、自定义 kernel 等；仅表示可选研究方向，不是全部交付承诺。自定义 kernel 并非必修。

## 4. 后训练学习主线

| 编号与主题 | 需要理解 | 实际操作与观察 | 建议验收证据 |
| --- | --- | --- | --- |
| T1 数据与目标 | 预训练、SFT 与偏好目标的区别；模板、labels、mask、截断和打包 | 逐 token 检查训练样本；追踪一个 batch 的 loss 来源 | 样本检查记录；数据或 mask 问题诊断 |
| T2 SFT 执行 | 前向、反向、优化器、学习率、梯度累积与有效 batch | 检查可训练参数、梯度及一次更新；运行训练与独立评估 | 更新链路、训练和验证记录、训练前后输出对照 |
| T3 参数与资源效率 | 全参数更新和 LoRA 的差别；权重、梯度、优化器、激活的资源组成 | 实验 LoRA；选择混合精度、检查点或累积等资源策略 | 参数更新范围与资源账本；时间、内存及效果取舍 |
| T4 训练诊断与恢复 | 过拟合、遗忘、数值异常、随机性和状态恢复 | 选择代表性问题排错；中断、恢复、保存与重新加载 | 恢复验证、问题诊断与产物重新加载结果 |
| T5 效果评估 | 泛化、泄漏、对照组、评估波动与任务外退化 | 固定训练/验证/测试边界；比较训练前后及必要对照 | 有样本级证据的评估报告；解释 loss 与效果的关系 |
| T6 离线偏好优化（建议纳入，待确认） | 偏好对、序列概率、参考策略及相对目标 | 选择一种方法，如 DPO；检查数据与目标，观察偏好和行为变化 | 偏好数据检查、目标计算记录、独立行为评估 |
| T7 在线强化学习受控实验 | 当前策略采样、奖励、优势、概率比、更新约束和循环 | 选择一种方法与可验证任务；观察生成到更新的全过程 | 采样记录、奖励分布、更新诊断、固定任务评估及成本分析 |

T7 不预先限定具体算法。是否需要参考模型、价值模型或其他状态，按所选算法说明，不能将某一种算法的结构当作所有在线强化学习的共同要求。首次实验采用可验证奖励，学习训练闭环；不承诺通用聊天对齐或大规模能力提升。

## 5. MoE 跨主线专题

- 理解：总参数与激活参数、路由、Top-k、分发、专家计算和聚合；区分模型权重存储、实际计算和通信成本。
- 推理实践候选：检查路由分布与专家负载；观察不同 batch 下的计算与搬运；比较一个本地执行优化。
- 训练实践候选：检查路由及专家的可训练范围、实际梯度与更新覆盖，评估任务变化与路由变化。
- 证据：真实运行中的路由统计、资源与性能记录、至少一个问题分析。最终实验深度待资源与学习预算确定。
- 专家并行与跨设备通信可以先完成机制和预算分析；如果未进行多设备实验，不能声称已掌握其实际调优或验证了性能收益。
- 模型方案待定：以 MoE 为主对象，或固定一个主模型加一个 MoE 专题对象；不因此建立任意模型适配体系。

## 6. 模型可解释性持续观察专题

定位：作为独立专题增强对 LLM 的理解，同时嵌入推理、SFT、MoE 和在线强化学习等阶段。它是一项逐步积累的观察工作，不安排为主线结束后才开展的一次性实验。

当前范围仅包括方法操作与结果：

- 能使用选定工具，知道输入是什么、输出表示什么、如何保存与重复观察，以及结果有哪些使用限制。
- 暂不要求理解方法的数学或算法原理、自行实现工具、研究新解释方法，或据此优化模型与解释方法。
- 不以得到清晰图像、找到确定机制或改善任务效果为完成标准；没有发现稳定现象或结论仍不确定，也应保留记录。

建议采用的持续观察流程：

1. 建立一小组固定观察样例，保留输入、目标行为及选择理由；后续可补充异常样例，不能覆盖原有记录。
2. 在初始模型上记录观察基线；在训练前后和选定阶段检查点重复观察。优化实验按需加入，不要求每步训练都采集。
3. 按明确问题选择观察方法，例如比较输入变化、不同层的中间结果或 MoE 路由分布。具体工具与方法待模型和环境确定后选择，不将一般运行指标自动等同于可解释性结论。
4. 同时保存最终输出与所选内部观察结果，区分“看到了什么”“可能说明什么”和“尚不能说明什么”。注意力图、激活相关性和模型生成的自我解释均不能单独证明因果机制。
5. 如果后续选择干预实验，单独保存干预条件和对照；干预不是当前必交付要求，其结果也需注明适用条件。
6. 根据观察收益、稳定性和采集成本完善方法，记录方法与配置版本。方法变化后保留旧结果；必要时重跑固定样例，避免把测量方式变化误判为模型变化。

每条观察至少记录：问题、模型与检查点、样例标识及实际输入、工具与方法版本、关键配置、输出及原始观察产物、现象描述、解释假设和局限。涉及随机生成时记录采样条件。

验收侧重过程：形成初始基线与后续阶段对照，观察记录可复现，方法演进可追踪，结论不超出证据。不套用其他主题的原理理解、性能收益或故障修复要求；不预设观察一定产生新机制发现。

观察工具不得绕过既有推理或训练主路径。需要修改执行或注入干预时，以独立实验明确标记；性能测量与带观测工具的运行分开，记录额外时间与内存开销。方法选择不应把项目扩展成解释工具兼容平台。

## 7. 每个主题的实验与验收约定

下列为主线通用约定；可解释性专题按第 6 节的范围裁剪，不新增原理理解与优化要求。

1. 定义问题与假设：希望解释或改善什么，哪些变量需要控制。
2. 选择实践方式：最小机制实验、真实链路观测、针对性修改与优化，可组合。
3. 确立行为基线：记录已知正确链路，说明比较对象、误差容限与评估依据。
4. 保存复现条件：代码与依赖版本、模型和数据版本、设备、精度、输入输出长度、batch、种子及关键配置；性能实验记录预热、同步、重复测量和后台负载条件。
5. 保存观察证据：按需要记录张量摘要、缓存、梯度、训练曲线、profile、样本输出；不要求保存所有大张量。
6. 分析结果：解释正确性、效果、时间和内存取舍，区分实测事实与推断。
7. 检查迁移边界：模型规模、上下文、batch、并发或硬件变化后，哪些假设会失效，如何复验。

性能实验与诊断实验可分开运行，避免观测工具的开销污染性能结论。推理记录负载条件与延迟/吞吐；训练同时记录处理量、每步耗时、生成采样成本（如适用）、峰值内存和效果，不能只报告 loss 或单步速度。

## 8. 迁移能力的最终验收建议

给出一个尚未实际运行的更大模型或不同规模负载，完成以下分析：

- 画出推理与后训练的数据流和主要状态，指出与已完成实验的共性和差异。
- 根据已知架构与精度，估算权重、KV cache 及训练状态等主要资源，写明未知项。
- 预测可能瓶颈，提出有优先级的测量计划与优化候选，不把预测当作结论。
- 说明哪些既有经验可以直接参考，哪些必须重新验证，以及哪些需要多设备等新条件。

这项验收证明分析与实验设计能力；实际更大模型的优化能力仍需要对应环境的运行验证。

## 9. 阶段边界与下一轮讨论

建议按依赖推进：目标与验收确认 → 资源与选型可行性验证 → 推理和 SFT 基线 → 双主线优化与诊断 → MoE/偏好专题及在线强化学习 → 迁移分析。推理优化与训练效率阶段应交替安排，避免全部资源投入单侧。具体进度与验收数值后续确定。

可解释性观察从初始基线开始贯穿各阶段，在约定节点重复采集与比较，随项目逐步完善方法，不作为末尾一次性阶段。

下一轮先确认三个范围问题，再进入选型：

1. 推理范围是否包括多请求服务层面的调度优化，还是以单请求/离线批处理为主？两者可兼有，但深度需明确。
2. 是否将离线偏好优化纳入核心学习主题？当前是建议，尚未确认。
3. MoE 希望完成实际推理与后训练实验，还是先以实际推理及训练机制观测为范围？最终承诺需结合资源验证。

以上问题不要求用户预先理解所有技术细节；讨论时应先解释其学习收益、增加的复杂度与必要条件，再作取舍。
