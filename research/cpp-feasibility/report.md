# C++ 主导路线的首轮可行性验证

日期：2026-10-22。状态：关键计算与恢复机制验证通过，尚未完成完整目标模型验收。本文是实验记录，正式实现约定见 [实现约定](../../docs/implementation.md)。

## 目的与实现边界

验证使用 C++ 主导项目是否会因当前 M4 / 24 GiB 硬件、MLX 接口或后训练基础能力而受阻。实验入口见 [说明](README.md)，不替换正式实现，不下载完整权重。

MLX 0.32.4 提供底层张量、自动微分、GPU 内核及张量文件能力；C++ 代码负责计算组合、LoRA 和训练控制。Python / MLX LM 0.32.2 作为对照，不承担被测工作进程的执行。链接清单保存在报告中，C++ 程序不链接 Python 解释器。SDK 当前由根目录 Python 环境供应，这一安装布局不等于运行时必须嵌入 Python；正式 SDK 的安装、版本与打包方式仍需设计。

## 实测结果

最终 [完整证据](evidence/result.json)：65 项数值/状态检查通过，4 项负面路径均按预期失败。计数包含同一机制的多个张量，不代表 65 个独立算法。

| 验证项 | 输入与结果 | 适用边界 |
| --- | --- | --- |
| 构建及 GPU | C++17 / Apple Clang 17，成功链接 MLX，明确使用 GPU | 使用已安装 SDK；没有测试源码构建、独立分发或其他平台 |
| 量化 LoRA | 4-bit、group 64；投影权重 `[1024,2560]`，对应 4B 注意力 K 投影维度；rank 4、4 个 token；FP32/BF16 激活与 adapter 均能反向 | 合成权重和单投影，不是预训练模型训练 |
| 冻结量化计算的输入梯度 | 对照反量化等价计算，通过 | 证明此算子能向前层传梯度；不是整模型梯度正确性证明 |
| 梯度检查点 | 重算后的三类梯度与直接计算对齐 | 单投影目标；实际层级划分与收益待测 |
| 注意力、位置及卷积 | 16 Q heads / 4 KV heads、head dim 256、8 tokens；因果前向与逐 token 前缀计算对齐；另测 RoPE、RMSNorm、分组卷积 | 未装配完整注意力层；卷积仅 4 通道，未验证完整 Qwen 位置语义 |
| GatedDeltaNet 递推核心 | 16 Q/K heads、32 V heads、head dim 128、8 tokens；输出、FP32 状态、六类输入梯度及分块状态对齐；门值方向有限差分通过 | 已提供归一化后的 Q/K 与激活后的门；无完整层、padding mask、长序列测试 |
| 原生融合递推 | C++ `fast::gated_delta_update` 的前向及六类输入反向与组合算子参考对齐 | FP32、相同短序列；尚未比较混合精度、长序列性能及内存 |
| 自定义 Metal | C++ 创建、执行逐元素内核，结果对齐 | 只证明扩展入口可用；未实现该内核自定义反向或性能优化 |
| Adam 更新 | C++ 手写 bias-corrected Adam 与 MLX Python Adam 的首步参数和动量对照通过 | 固定学习率，无调度器或梯度累积 |
| 完整小实验恢复 | 连续 8 步，对比第 3 步保存退出后新进程恢复；参数、动量、随机 key、样本编号和 loss 历史完全一致 | 微型训练，不是 4B LoRA 检查点 |
| 信号暂停 | 第 3 步测试会合点发送 SIGINT，正常退出，新进程恢复与连续运行完全一致 | 已确认工作进程结束；未测真实模型内存压力或长 kernel 的暂停时间 |
| 错误拒绝 | 缺失检查点、身份不匹配、截断文件、覆盖已有运行均拒绝 | 未做任意数据位损坏检测或崩溃注入 |

FP32 跨语言多数对照相同；BF16 允许声明容差，最大梯度绝对差约 `1.53e-5`，不宣称逐位一致。Adam 首步参数最大绝对差约 `6.89e-8`。完整恢复对照使用严格相等，不以容差掩盖状态遗漏。

最终算子工作进程报告的 MLX 分配峰值约 190 MiB；融合递推反向独立进程约 25 MiB。这些是短合成实验、不同执行路径的分配记录，不是进程 RSS、稳定性能基线，也不能外推为 32 层模型内存或相互比较优化收益。

本次完成时项目物理占用约 1.28 GiB，卷空闲约 60.5 GiB，符合资源规则。测试运行同步结束，无训练常驻进程。模型权重未下载，磁盘占用不含完整模型。

## 实际遇到的问题

1. wheel 的 CMake 导出包含打包机器的绝对 Xcode framework 路径。本机编译虽能链接但有警告；现改为在当前 SDK 查找同名 framework 后链接，重新构建无该警告。正式依赖集成需要保留此检查，不能直接假定 wheel 的 CMake 配置可移植。
2. MLX 为没有 `.safetensors` 后缀的保存路径自动追加后缀。首次临时路径以 `.tmp` 结尾，实际写入文件名与后续 `fsync/rename` 路径不同，恢复实验失败。改为 `.tmp.safetensors`，重新验证原子保存和新进程恢复；没有改成跳过保存或从头训练。
3. C++ 与 Python 共享底层 MLX 并不保证低精度表达式计算顺序完全相同。BF16 需要数值容差和效果评估，不能套用恢复状态的逐位一致标准。

## 对正式路线的影响

本轮没有发现必须依赖 Python 才能完成自动微分、量化 LoRA 或融合递推反向的基础接口缺口。此前对这些能力的疑问可以缩小到具体模型集成与资源问题；不应继续把“C++ 无法训练”作为未经验证的假设。

下一关口依次为：

1. 固定 SDK 集成方式、参数命名/注册与文件格式；确定 tokenizer 和聊天模板的可复用组件，使用固定样例对齐 token IDs。
2. 完整装配目标模型所需的注意力层、递推层和语言模型头；先以合成权重核对逐层输出、混合 cache 与梯度，再加载一个固定 revision 的 4B 执行产物。不建设通用模型框架。
3. 实际 4B 的短推理、LoRA 更新与完整恢复，测峰值内存、时间、暂停延迟和保存空间；通过后才安排长训练与 RL。
4. 9B 的内存、耗时及磁盘需要二期独立验证；本轮不作可运行承诺。受控 RL、可解释性观察和前沿优化接口仍需后续实现，不能因本轮通过而标为完成。

现有固定模型、固定硬件和磁盘规则保持有效。完整模型仍可能需要调整序列长度、微批次、重算策略或局部算子；这些选择须以实际正确性和资源测量为依据。
